# Search a mentioned name on Google Maps again after three months

## Goal
`LOOKUP_VENUES` searches a name again when its last lookup is older than `LOOKUP_RETRY_MONTHS` (3) and the name is still unmatched, so a place creators posted about before Google listed it (the usual order for an opening) gets matched by the next quarter instead of never.

## Why
`VenueLookup` has no date (only the normalized query and the result count), and `lookupNames` skips every query ever stored, found or not. New places are exactly the ones mentioned first and listed later; their later mentions stay `none`, their reports never build, and the lead score's new-place bonus never sees them. The cost of a retry is three Google Maps results (~$0.012) per stale name.

## Scope
- In: `VenueLookup.createdAt` (the base class may already carry it; else add it and a migration), `lookupNames` skipping only lookups younger than three months, the retry updating the row; the unmatched-names query unchanged.
- Out: retrying names that matched since (they are not in `unmatchedNames`); OSM-based retries.
