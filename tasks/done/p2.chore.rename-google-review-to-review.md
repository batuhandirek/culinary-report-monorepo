# Rename the GoogleReview entity to Review now that it holds TripAdvisor reviews too

## Goal
`GoogleReview` / `google_reviews` / `GoogleReviewService` / `GoogleReviewRepository` become `Review` / `reviews` / `ReviewService` / `ReviewRepository` (files renamed to match), and the DTO and frontend names that say "Google review" for a row of either platform follow. No behaviour changes.

## Why
The table holds Google and TripAdvisor reviews (`platform: google | tripadvisor`, `ReviewPlatformEnum`), so the Google name misleads every reader. Nothing is released, so no shim is needed.

## Scope
- In: the entity class, table (a generated rename migration: check it renames, not drop + create, and keeps the data), file names, repository, service, every import (`grep -rn "GoogleReview\|google_reviews\|google-review" apps/backend/src`, raw SQL strings included: lead score, trends, portal facets, report-city, report-signals, review watch), the admin DTO `AdminGoogleReviewOutputDto`, `npm run create:client`, frontend uses, the domain skill.
- Out: changing what any query returns; `GOOGLE_REVIEWS_ACTOR` and the Google-only review watch keep their names.

## Pointers
- `apps/backend/src/modules/venues/entities/google-review.entity.ts`, `services/google-review.service.ts`, `repositories/google-review.repository.ts`, `services/tripadvisor-review.service.ts`.
