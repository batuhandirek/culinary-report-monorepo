# One `profiles` atom for the Instagram and TikTok profile scrapes

## Goal
Every `apify/instagram-profile-scraper` and `clockworks/tiktok-profile-scraper` run goes through one atom, `pipeline/atoms/profiles/` (`profiles.run`), built like `pipeline/atoms/places/`: a caller names the platform and the handles, and whether it wants the profile only, the latest ten, or the posts since a day; the atom builds the input in a step, runs the actor as a child on the `apify` queue with the operation as the run's owner, and saves accounts, snapshots and posts through `AccountScrapeService`'s one save per platform in a step. `AccountScrapeService.scrape`, `fillFollowers`, `trackProfiles` and the twin lookup keep only their plans and their reading of the result.

## Why
Six operations run the two profile actors (`scrape-accounts` month and week, `creator-watch`, `account-followers`, `profile-track`, `find-own-accounts`, `read-mentioned-profiles`): two already run them as children from their bodies (`creator-watch`, `read-mentioned-profiles`, with `instagramProfileRun` / `tiktokProfileRun` as plain data), the rest inline inside a step. One atom makes the six the same shape and puts every profile run on the `apify` queue.

## Scope
- In: the atom; `AccountScrapeService` split into plan (`planWatched`, `planFollowers`, `planTracked`, …) and save (`saveInstagramScrape`, `saveTiktokScrape` as today, the inline `scrape…` methods gone); `AccountTwinService.lookup` split the same way; the six workflows composed plan → `profiles.call` → save; the suites rewritten; the skills and `operations.md`.
- Out: the search actors (`tiktok-search-atom`, `instagram-hashtags-atom`).
