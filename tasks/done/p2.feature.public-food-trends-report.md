# Publish a periodic public food trends report per city

## Goal
A public page per city and quarter ("Berlin food trends, Q3 2026"): most searched and fastest rising topics, breakout dishes from rising related queries, the most talked-about topics on social media, openings and closures by topic. It links to the sample report sign-up.

## Why
Marketing and lead generation from data we already pull; nothing to spend.

## Scope
- In: year-over-year changes (pull 24 months, or keep each month's stored figure, so autumn's ice-cream dip doesn't read as a trend), comparable levels across topics (pull in groups of five with one shared anchor topic and rescale, since a term pulled alone only compares with itself), the page (SSR, SEO), an admin "publish" step so nothing goes out unchecked.
- Out: per-venue data on the public page (only topics and public venue names in Google's own rising queries).

## Pointers
- `SearchInterestService`, `TrendService`, `VenueStatusChangeService.quarter`

## Acceptance
- [x] PGlite: anchored levels rescale across groups.
- [x] The page renders for Berlin's last quarter after an admin publishes it.

## Open questions
- Which anchor topic? Assumption: pizza (always high, stable, every city has it).
