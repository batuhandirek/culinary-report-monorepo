# Match mentions one mention a workflow

## Goal
`pipeline/match-mentions/` matches a city's unmatched mentions one mention a workflow: the code's ranking and sure matches in a step, `VenueMatchAgent`'s call (when the code can't decide) a `DurableLlmService` child that waits for an account, the decision saved in a step. `VenueMatchAgent` and its input building move from `social` into `pipeline/match-mentions/agents`, `MentionMatchingService` keeping the candidates as data and the saving.

## Why
Today `MatchMentionsWorkflow.matchCity` runs `MentionMatchingService.match` in one step: its agent calls are plain, so a provider out ends the step (close calls left undecided until the next hour), the ledger files the calls under the city's run, not the mention, and a crash re-runs the whole batch.

## Scope
- In: per-mention plan → agent child → save; the chain branch question (`branchId`) the same way; `sweepTags` and `matchByTags` stay city-wide steps; the eval (`ingestion-eval`) before and after, as `decideMatch` and `toCandidateVenues` must keep their inputs.
- Out: changing the matching rules themselves.
