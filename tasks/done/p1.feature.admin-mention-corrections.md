# Let an admin fix a mention's venue match and rebuild the report

## Goal
From a post page or a venue's Mentions tab an admin can relink a mention to another venue, unlink it, or mark it as not a venue; the correction survives re-matching; one click rebuilds the affected report.

## Why
Matching is automatic (trigram, then an LLM for close calls) and the admin can only look at it. A wrong match puts another venue's praise or complaints into a report that is sent to an owner, and today the only fix is SQL. Report credibility is what is being sold.

## Scope
- In:
  - `MentionMatchMethodEnum.MANUAL` and `IGNORED`; `match()` never touches a `MANUAL` or `IGNORED` mention, even with `rematch`.
  - `PATCH /admin/mentions/:id` with `{ venueId: string | null, ignored?: boolean, note?: string }`.
  - A venue picker dialog (search by name through `listVenues`) used from the mention rows on the post page and the venue Mentions tab; an "Unmatched" filter on `/admin/posts` (mentions with `none`, most viewed first) to link by hand.
  - "Rebuild report" for venue × month on the venue Reports tab (calls the existing `POST /admin/reports`).
- Out: editing the LLM's extracted praise, complaints or dishes.

## Acceptance
- [x] PGlite: a `MANUAL` mention keeps its venue through `match({ rematch: true })`; the PATCH sets venue and method; `IGNORED` mentions leave `summarizeReport` input.
- [x] UI: relink from a post page, rebuild from the venue page. (Relink verified in the browser; the Rebuild action is on the Reports tab but was not clicked: reports are rebuilt by the coordinator at the end.)
- [x] `domain-venues-and-reports` has the rule that manual matches are never overwritten.
