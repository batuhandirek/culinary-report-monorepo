# One `tiktok-search` atom for every TikTok search run

## Goal
Every `novi/advanced-search-tiktok-api` run goes through one atom, `pipeline/atoms/tiktok-search/` (`tiktok-search.run`), built like `pipeline/atoms/places/`: a caller gives the queries, the window (`WEEK` / `MONTH` / `THREE_MONTH`) and the results per query, and how the finds are recorded (a city search's kinds, a venue search's venue); the atom builds the input in a step, runs the actor as a child on the `apify` queue with the operation as owner, and saves the posts and their finds through `SocialScrapeService`'s one save in a step.

## Why
`scrape-tiktok` (month and week) and `scrape-venue-social` (month and week) run the search actor inline inside their steps through `SocialScrapeService.scrapeCityTikTok` / `scrapeVenueSocial`, which plan, call and save in one method: no `apify` queue, no credit wait, a crash re-runs the step and pays again.

## Scope
- In: the atom; `SocialScrapeService` split into plan (the queries and limits per kind, the budget split) and save (the posts' upsert and finds, `linkPostSources`) for TikTok; the four workflows composed plan → `tiktok-search.call` → save; the suites; the skills and `operations.md`.
- Out: the Instagram half of `scrape-venue-social` (the location actor), which gets the `instagram-hashtags-atom` or an atom of its own.
