# Scrape six months of reviews the first time a venue enters the report set

## Goal
A venue's first report has a previous month (reviews, stars, reply rate), "what followed what" (buzz → reviews, complaint times: both need the five or six months before) and the lead score's "nameable problem" from real history, because the first `SCRAPE_REVIEWS` that covers a venue starts `REVIEW_BACKFILL_MONTHS` (6) before the report month instead of at its first day.

## Why
Reviews are scraped only for the month's report brands' branches and their competitors, from the month's first day. A brand that enters the top 20 (about five a month on dev) has no earlier review stored, so its first report shows no deltas, no patterns section, and its competitors likewise. The month scrape already keeps every review from its start date and `params.since` already exists for manual backfills; this only decides `since` per venue.

## Scope
- In: in `SCRAPE_REVIEWS`, split the venue set into "has any stored review" (start at the month's first day) and "never scraped" (start six months back), two actor runs inside the same budget, the backfill's share capped (say 40 %) so the month's own reviews always come first; the run result says `backfilled` venues; a rating snapshot is written as today.
- Out: backfilling the rating history (snapshots are dated the scrape day; no source for past ratings); TripAdvisor (its page find and month scrape stay as they are); posts.
