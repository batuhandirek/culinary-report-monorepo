# Terms: every wording, linked to topics like a graph

**Read first**: the brief `statements-and-concepts`, then this. Needs `topics-tree` done (one `Topic` tree with
aspects). Program order: `topics-tree` → **terms** → `statements` → `reread-sources-with-new-agents` →
`google-tags-as-statements` → `talked-about-pages`.

## Goal
`Term` (table `terms`) holds every wording the system has seen, as written in its source's language, keyed across
spellings and plurals; `TermTopic` (table `term_topics`) links a term to zero, one or many topics of any kind. A
term is decided once (a name match, agent C, an admin) and re-decided when topics change; an admin's links nothing
changes. Decided terms are part of `TopicIndex`, so everything that matches text today (mention cuisines, Google
categories, delivery menu items and sections, hashtags, Google's review tags) learns every decision through the
relink job it already runs. `DishName`, `Topic.aliases` and `TopicIgnoredWord` are gone.

## Why
"Spaghetti Vongole" on a Wolt menu is not pasta today although the dish name was decided pasta; "vegan döner" can
only be kebab, never also vegan; Google's "waiting time" has nowhere to go. The user (2026-10-29): keep every
wording as said ("Pommes", not "fries"), even one nothing links yet; link it later to one or many topics; change the
links any time; use the one table everywhere (menu items included).

## Scope
- In: the entities, the migration carrying dish names, aliases and ignored words across, `TermService` (the one
  writer), agent C, the `terms` backlog (replacing `feedback-dish-names`), the index built from topics + decided
  terms, the relink order, the admin's Dish names tab made a plain Terms tab (same layout over terms; the designed
  UI is `talked-about-pages`), the Google-tag stopgap reading terms' links.
- Out: statements (the rows still are `feedback_points`), writing Google tags as statements, re-reading sources,
  the designed admin UI.

## Entity changes (this phase only)
- New `Term` (`terms`, `MikroOrmSimpleEntityAbstractClass`): `key` text unique (`termKey`: today's `dishKey` —
  accents, punctuation and per-word plurals folded, another script kept), `name` text (the spelling seen most),
  `decidedBy` match | ai | admin | null, `decidedAt`, `suggestion` text nullable. New `TermTopic` (`term_topics`):
  `term` (cascade), `topic` (cascade), `rank` int; unique term × topic.
- `DishName` → dropped (rows become terms; `dish_names.topic_id` → one `term_topics` row, `decidedBy`/`decidedAt`/
  `suggestion` carried). `Topic.aliases` → dropped (each alias → a term `decidedBy admin` linked to the topic).
  `TopicIgnoredWord` → dropped (each → a term `decidedBy admin` with no link).
- `FeedbackPoint`: `dishKey` stays the term's key (joins `terms.key`); `topic_id` (the old `foodTopic`) stays as a
  stopgap holding the term's first food-kind topic (`apply`), until `statements` replaces the rows with parts.
- `Hashtag` unchanged (keeps reading `exact`, which now knows terms).

## Order of work
1. Entities, module placement (`modules/topics` owns `Term` and `TermTopic`: the index needs them and `feedback`
   imports topics, not the reverse), migration: create tables, carry `dish_names` across (one `term_topics` row per
   linked name), aliases (from each topic's jsonb; the seed's aliases too, so `TOPIC_SEED` keeps `aliases` for tests
   but the migration turns them into terms), ignored words; then drop `dish_names`, `topics.aliases`,
   `topic_ignored_words`. Hand-written data part + generated schema part; apply at once.
2. `TopicIndex` built from topics + decided terms: the lookup maps a form to a list of topic keys (a term with two
   topics gives both; a topic's own key and label stay first); `exact(raw)` returns the first; new `exactAll(raw)`
   the list; `resolve` returns the list on a whole hit; `dishTopic` the first dish or drink among them. The seed
   suite's "no alias shadowed, every label resolves to its own topic" keeps holding with aliases as terms.
3. `TermService` (replacing `DishNameService`): `termKey`, `sync(index)` (new wordings from `feedback_points.dish`
   and from every venue's `details.reviewsTags` titles, decided at once by a name match when the whole wording is a
   topic's key or label), `decide({ limit })` (agent C: the pending terms most used first, every topic of every
   kind offered as `{ key, label, kind, parent }`, a list of keys answered, a `suggestion` for a missing topic;
   100 wordings a call; the `terms` backlog, priority 25), `apply(keys?)` (the stopgap column), `relink(index)`
   (after a topic change: a wording that is now a topic as a whole takes it; an agent decision whose topics are
   gone waits again; an agent "none" takes a topic created since that its suggestion names; admin links untouched),
   `list` / `change` for the tab (`change` takes a list of topic keys, `[]` for none, or `{ auto: true }`),
   `linksOf(keys)` for the stopgap. Registered as re-linker `terms`, **first** in the relink job, so the index the
   others use is rebuilt after it; then `mention-topics`, `menu-item-topics`, `hashtags`, then venue tags.
4. Agent C `TermTopicAgent` (mini; replaces `DishTopicAgent`): "which topics is this wording, as a whole": a dish
   → its dish topic and any diet or cuisine the wording itself states ("vegan döner": kebab, vegan; "Turkish
   breakfast": turkish, breakfast); a staff, place or payment wording → the aspect ("friendly staff": friendliness;
   "cash only": cash_only; "waiting time": wait); a word too general → none ("meat", "food", "special"); a specific
   thing no topic covers → none + suggestion ("Fries" once was one). Carries the POC rule: never answer nothing
   for a wording because it is odd; "none" is a decision, a suggestion a gift. Keep the dish examples of the old
   instructions.
5. `TopicService.create` / `update`: aliases API becomes terms (the dialog's aliases field lists the topic's admin
   terms; adding one creates a term; the 400 for an alias that names another topic whole becomes "that term is
   decided for X by an admin"); "Add to aliases" and "Dismiss" on the unrecognised-words tab create admin terms.
6. The Dish names tab → Terms tab, same component over `GET /admin/terms?cityId=&status=&q=&topicKey=&suggestion=`
   and `PATCH /admin/terms/:id` (a topic picker that allows several); counts: statements naming it (today's rows)
   and venues whose Google tags carry it; `TopicDishNames` → `TopicTerms` (the terms linked to the topic).
7. `DishNameService.reviewTagTopics` → `TermService.linksOf` (the brand summary and the venue page stay as they
   are until `google-tags-as-statements`).
8. Tests: `terms.spec.ts` (key folding, the index with terms: lists, shadowing, `exactAll`), `term.service.pglite.spec.ts`
   (carried names and aliases, sync from rows and tags, a match decision, the agent mocked with a two-topic answer,
   apply to the stopgap column, relink after a topic change and after an admin's link, the backlog), the menu-topic
   and food-topic-links suites: a decided term reaching a menu item and a mention cuisine after relink.
9. Skill: dish names → terms, the index rule, the relink order.
