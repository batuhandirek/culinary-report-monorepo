# Let an admin (or the owner) set a venue's booking-platform link so open tables can be sampled

## Goal
A venue can carry a booking link we set by hand (TheFork or OpenTable page); `SAMPLE_RESERVATIONS` uses it before Google's `reserveTableUrl` and the website, so a won prospect that books through a platform gets open-table samples.

## Why
`VenueReservationService.targets` finds the platform from `Venue.details.reserveTableUrl` or `Venue.website`. In Berlin all 492 reservation links on dev are `https://www.google.com/maps/reserve/...`, which names no platform, so the step skips nearly every venue (`noPlatform` in the run result). Quandoo, Berlin's main platform, shut down on 30 Sept 2026.

## Scope
- In: a nullable `bookingUrl` on `Venue` (not inside `details`, which scrapes merge into), an admin field on the venue page, optionally the portal settings; `reservationPlatformOf` on it first.
- Out: resolving Google's reserve link to the partner (needs a browser session), new platforms (resmio, Formitable: no actors found).

## Pointers
- `apps/backend/src/modules/venues/services/venue-reservation.service.ts` (`targets`), `util/reservations.ts`.
- `routes/(admin)/admin/venues/[venueId]/components/VenueDemandPanel.svelte`.

## Acceptance
- [x] PGlite: a venue with a hand-set TheFork link is sampled although its Google link is Google's own page.
- [x] The admin venue page edits the link. (Form in the "Demand and delivery" panel; PATCH covered by a controller PGlite test; checked in the running app: a Google link is refused inline, a TheFork link saves, clearing removes it — the dev row was left empty.)
