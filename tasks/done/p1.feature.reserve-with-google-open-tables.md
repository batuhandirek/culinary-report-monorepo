# Sample open tables from the Reserve with Google page, for every venue that has one

## Goal
`SAMPLE_RESERVATIONS` reads open evening slots from Google's own booking page (`google.com/maps/reserve`), which every partner platform feeds (OpenTable, TheFork, resmio, Formitable, …), with our headless Chrome instead of an Apify actor. It samples every open venue of the city that has such a page, not only won prospects, so the report can compare a venue's booked-out share with its competitors and the district. The partner behind the page is stored on the venue.

## Why
On the dev DB 492 of 4,466 venues carry a reservation link and every one is `https://www.google.com/maps/reserve/v/dine/c/<id>?…`, which names no platform, so the current sampler (`reservationPlatformOf`) skips all of them. Quandoo, Berlin's main platform, shut down on 30 September 2026. The Google page needs no login, no cookie and no consent click (checked 2026-10-18 with a cookie-less fetch: 200, the page itself, `in partnership with` in the HTML), takes the date, time and party size as query parameters, and costs nothing per load, so the whole city can be sampled, which is what makes competitor and district comparisons possible.

What the page looks like (checked in a browser on 2026-10-18 for a Berlin venue):
- URL: `https://www.google.com/maps/reserve/dine?c=<id>&ld=<YYYYMMDD>T<HHMMSS>&ps=2&hl=en`. `<id>` is the `c/<id>` segment of `reserveTableUrl` (the stable merchant id; every other query parameter of the stored link is session noise: `gei`, `sourceurl`, `opi`). `ps` is the party size, `hl=en` gives 12-hour labels. `ld` picks the date and the time the grid is centred on; the page may shift it (a `ld` of 19:00 came back centred on 21:00 once), so read the labels the page shows, never assume positions.
- The panel has three controls (Party combobox, a "Select reservation date" group, a "Select reservation time" listbox with options every 30 minutes) and, per bookable area ("Restaurant", "Hochtisch", "Family Sunday", …), a grid of nine quarter-hour buttons around the chosen time: a bookable slot is a button whose accessible name is the time ("8:15 PM", or "Selected: 8:00 PM"), a closed slot is a button with no name. Two loads per evening, centred on 19:00 and 21:00, cover 18:00–22:00.
- The footer reads "Booking times are provided in partnership with" followed by the partner's name ("OpenTable" for the venue checked).
- Availability changes go through `POST /maps/reserve/_/data/batchexecute?rpcids=fctN0|ffGVGc` (Google's internal RPC), so a plain fetch may not carry the grid; check whether the first server-rendered HTML holds the slots before reaching for Puppeteer. If it does, use fetch and keep Chrome out of it.

## Scope
- In:
  - A `ReservationPlatformEnum.GOOGLE` (`google`) with `GoogleReserveAvailabilityService implements ReservationAvailabilityProvider`: for each target and date, load the two windows, read every grid, count a quarter hour as open when any area lists it, store `slotsOpen` / `slotsAsked` (16) / `partySize` 2. A page that shows no grid at all for a date (closed that day, or not taking bookings) is `slotsOpen: 0` only when the page shows the date with no slots; a page that fails to load or shows a captcha / "unusual traffic" page stops the provider, keeps the samples already taken and fails the run (never retried, as the other providers).
  - The partner name from the footer → new nullable `Venue.reservationPartner` (text; set on every sample, so a venue that moves platform updates). Admin venue panel shows it.
  - The headless Chrome factored out of `ReportPdfService.getBrowser` into one shared `BrowserService` (`modules/browser`, or `shared/`): one browser, a page per job, `--disable-dev-shm-usage` and the `PUPPETEER_CACHE_DIR` notes in `nixpacks.toml` already cover it. The PDF service uses it.
  - `reservationPlatformOf` recognises `google.com/maps/reserve/…` (`GOOGLE`); `VenueReservationService.targets` order stays `bookingUrl`, `reserveTableUrl`, website; `setBookingUrl` accepts a Google reserve link too (the admin pastes it from Maps when the scrape missed it).
  - Venue set of `SAMPLE_RESERVATIONS` (in `PipelineService.runStep`): every open venue of the city with a sampleable link, ordered won prospects, then the month's report venues, then their competitors, then the rest by `leadScore`, capped by a constant (`RESERVATION_SAMPLE_MAX_VENUES = 600`); the run result reports `venues`, `noPlatform`, `samples`, `byPlatform` and `capped`. The Apify providers take the same set inside the step's budget (TheFork ~$0.006 a venue; OpenTable one run per date).
  - Pacing: a pool of two pages, a jittered pause of 1–2 s between loads, venue order shuffled inside each priority band. 500 venues × 2 dates × 2 windows ≈ 2,000 loads ≈ an hour; the step already runs alone in the one-at-a-time queue.
  - The report's `ReportDemand.platform` for `google` prints "Reserve with Google" plus the partner when known ("via OpenTable"); `PLATFORM_NAMES` in `report-signals.service.ts` and `PLATFORMS` in `ReportBusyness.svelte`.
  - `ReservationAvailabilityProvider`'s doc comment (it says every implementation runs an Apify actor), the domain skill's "Open tables" bullet (WON-only, Google page skipped) and the test list.
- Out: showing competitors' and the district's booked-out share (`report-competitor-demand`); booking anything; party sizes other than two; resolving the partner to a direct provider.
