# Lead the report's price block with the venue's own kind of food

## Goal
"Your prices next to theirs" (`ReportData.prices.menu`) opens with the venue's primary food topic against the same on the competitors' (else the district's) menus — "your ramen €14.50, theirs €12.90" — before the median main course, which mixes a burger with a salad.

## Why
`MenuTopicService.pricePosition(venue, otherVenueIds, month, dishes)` (food-topics) already returns `PricePosition.topic` (`TopicPrice`: key, label, price, othersMedian, othersWithTopic, diff). `ReportSignalsService.prices` (`reports/services/report-signals.service.ts`) still calls the pure `pricePosition` without a topic, so the report never shows it. It was left out of `menu-items-as-food-topics` because another session owned the reports module at the time.

## Scope
- In: `ReportSignalsService.prices` calls `MenuTopicService.pricePosition` (reports already imports `FoodTopicsModule`, which exports it) or passes a `MenuTopicMatcher` to `pricePosition`; `ReportPrices.menu.topic` (optional); `ReportPrices.sentence` / the prompt lead with it when the venue and at least one other menu have the topic; `views/report/ReportPrices.svelte` shows the line.
- Out: scraping more menus (only report venues and competitors have them).

## Pointers
- `apps/backend/src/modules/reports/services/report-signals.service.ts` (`prices`), `reports/interfaces/report-signals.interface.ts` (`ReportPrices`)
- `apps/backend/src/modules/food-topics/services/menu-topic.service.ts`, `venues/util/delivery.ts` (`pricePosition`, `TopicPrice`)
- `apps/frontend/src/views/report/ReportPrices.svelte`
- Tests: `reports/tests/report-signals.pglite.spec.ts`
