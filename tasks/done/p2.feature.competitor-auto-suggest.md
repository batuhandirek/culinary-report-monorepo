# Suggest a venue's competitors instead of picking them by hand

## Goal
The venue's Competitors tab offers five suggestions (same category or cuisine, same or neighbouring district, similar price level, most mentioned first) that one click adds; a "fill competitors for the top venues" action does it for every report venue without any.

## Why
The comparison section is the report's most persuasive page, and it is empty unless an admin remembers to pick competitors. With twenty to fifty reports a month that does not scale, and prospects (sample reports) never get it.

## Scope
- In: `GET /admin/venues/:id/competitor-suggestions` (`VenueCompetitorService.suggest`: food venues, not the venue itself, score = category match + cuisine match from mentions + district match + price match + log(mentions)), the tab UI, a bulk action on the pipeline page for the current top venues. Suggestions never add themselves without a click, except the explicit bulk action.
- Out: automatic competitor changes month to month (stability of the comparison matters).

## Pointers
- `apps/backend/src/modules/venues/services/venue-competitor.service.ts`, `controllers/admin.venues.controller.ts`, `entities/venue.entity.ts` (`category`, `categories`, `priceLevel`, `district`).
- `apps/frontend/src/routes/(admin)/admin/venues/[venueId]/components/VenueCompetitorsTab.svelte`.

## Acceptance
- [x] PGlite: a döner place in Kreuzberg gets döner and kebab places in Kreuzberg and Neukölln first, never itself or a closed venue.
- [x] One click adds a suggestion; the bulk action fills venues that had none.

None.

## Log
- 2026-10-17: Districts are Berlin's 12 Bezirke ("Friedrichshain-Kreuzberg"), so "neighbouring" is a hand-written border list (`areNeighbourDistricts` in `berlin.constant.ts`). Kinds of food go through a new shared `venues/util/cuisine.ts` (`normalizeCuisine`), also used by the trends task: "Kebab shop", "Doner kebab restaurant", "Döner", "Kebap" are all `kebab`. Generic Google categories (fast food, takeout, halal, snack bar…) don't count as shared food. A candidate must share a kind of food; a venue with a district only gets same or neighbouring districts. Price level is almost never set in dev data (only a handful of venues), so it rarely scores.
- 2026-10-17: The bulk action is `POST /admin/pipeline/fill-competitors` (`PipelineService.fillCompetitors` → `VenueCompetitorService.fill`), a button in a "Competitors" panel on `/admin/pipeline`, not a pipeline step: it is synchronous, free, and an explicit click. Ran it in dev for September 2026: 19 of the top 20 venues got 5 competitors each (95 rows), Döner Pro kept its 3.
- 2026-10-17: Done. Tests: new `venues/tests/venue-competitor-suggest.pglite.spec.ts`, `venues/tests/cuisine.spec.ts`.
