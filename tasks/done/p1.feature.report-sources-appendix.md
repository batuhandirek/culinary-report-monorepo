# Add a sources appendix to the report listing every post and review it counts

## Goal
The report ends with an appendix: every post about the venue (date, platform, creator and followers, views, paid/gifted and did-not-visit flags, one-line summary, link) and every Google review of the month (date, stars, excerpt, answered or not, topics raised), plus a short "how we count" note. On screen the appendix is collapsed behind one control; in the PDF it prints after the footer.

## Why
The owner has to be able to check a claim ("wait was criticised in 23 % of your written reviews") against the reviews themselves, or the report reads as AI guesswork. The list also doubles as the owner's to-do list (the unanswered reviews are right there) and proves the post count is real. Review tools in the market (Momos, Harmo, RestoData) all put the item list behind the aggregates.

## Scope
- In:
  - `ReportData.reviews.list`: all of the month's reviews, newest first: `reviewId`, `publishedAt`, `stars`, `excerpt` (≤ 240 chars of the translated text, else the original), `replied`, `praise` / `complaints` topics. No reviewer names (the entity stores none). Include the review URL if the actor item carries one (check `reviewUrl` on `compass/Google-Maps-Reviews-Scraper` items; store it on `GoogleReview` if so).
  - Posts: `ReportData.posts` and `ownPosts` already hold every post; the appendix lists all of them, not the six cards.
  - `ReportView`: an "Appendix: sources" section, `break-before-page`, dense tables with repeating `thead` and `break-inside-avoid` rows; collapsed on screen (a disclosure), expanded in print.
  - The "how we count" note: posts found by our searches only; topic counts are sources, not points; own account kept apart; reviews from Google for the month.
  - Rebuild existing reports: stored `ReportData` without `reviews.list` fails the response type (same rule as `competitors`).
- Out: linking to a TikTok creator's profile (the post link is enough); comments under posts.
