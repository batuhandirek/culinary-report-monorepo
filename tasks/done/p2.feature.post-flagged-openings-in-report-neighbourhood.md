# Count post-flagged openings in the report's "Openings and closures nearby"

## Goal
`ReportData.neighbourhood.changes` counts, next to the scrapes' openings, the district's venues a matched post said had just opened (`Mention.isNewOpening`), so the report's line is not empty until January 2027.

## Why
`VenueStatusChangeService.quarter`, `newVenueIds` and the lead score already read post-flagged openings; the report's neighbourhood line reads `inDistrict`, which stays scrape-only, so it shows nothing in Berlin until the second city list.

## Scope
- In: `VenueStatusChangeService.inDistrict` (or a sibling) also returning post-flagged openings (`source: 'posts'`, the same rules as `quarter`'s private `postOpenings`: matched, open, under `LEAD_NEW_PLACE_MAX_REVIEWS`, a venue already opened by a scrape listed once); `reports/util/neighbourhood.ts` and the report view naming the source if the copy needs it; the highlights prompt only if the line reaches it.
- Out: writing `VenueStatusChange` rows from posts.

## Pointers
- `apps/backend/src/modules/venues/services/venue-status-change.service.ts` (`inDistrict`, `postOpenings`)
