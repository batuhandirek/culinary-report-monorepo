# Admin pages for the durable workflows and the money ledger

## Goal
`/admin/workflows` (runs with status, queue, schedule, steps and their stored results; cancel, resume, fork; the queues and schedules with trigger/pause) and a Money page (`/admin/money`: the LLM spend by agent, model, provider, day, city and purpose over a chosen range; every provider's credit with the newest snapshot, the spend since and what is left; a form for a manual snapshot and a refresh button for Apify), both over the APIs that exist.

## Why
The backend answers every question now (`GET /admin/workflows…`, `GET /admin/spend/llm`, `GET /admin/spend/credits`), but the user has no screen for it: what runs, what each step stored, what the day's reading cost, whether a top-up changed the Apify room.

## Scope
- In: the two pages, a menu entry each (`ADMIN_MENUS.ts`), the client regenerated (`npm run create:client`), the run detail reachable from the Data page's run rows once `pipeline-runs-as-workflows` links them.
- Out: charts beyond a simple per-day bar; editing budgets from the Money page (a later slice: city step budgets informed by the ledger's actuals).

## Pointers
- `apps/backend/src/modules/durable-workflows/controllers/admin.workflows.controller.ts`, `apps/backend/src/modules/spend/controllers/admin.spend.controller.ts`
- `apps/frontend/src/constants/ADMIN_MENUS.ts`, `apps/frontend/src/routes/(admin)/admin/data` (the list/detail conventions)
