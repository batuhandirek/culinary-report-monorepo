# Make the city a configurable row, so a second city or country is data, not code

## Goal
A `City` row holds everything the pipeline knows about a place, and every step, cron, query and prompt reads it from there. Adding Munich, Vienna or Istanbul is an admin form, with no code change and no deploy. Berlin becomes the first row, seeded from today's constants, which are then deleted.

## Why
`PIPELINE_CITY`, `PIPELINE_LOCATION`, `BERLIN_DISTRICTS`, `BERLIN_HASHTAGS`, `BERLIN_SEARCHES`, the `location: 'DE'` TikTok region, `'berlin'` in the name stopwords and "Berlin" in the extraction prompt are all constants. The user will run other cities and countries; each needs its own sources, districts, language, region and budgets, and its own monthly run. Localisation of the app is not needed; the report language is (decision `report-language`).

## Scope
- In:
  - `City` entity: `slug`, `name`, `country` (ISO-2), `timezone`, `language` (default report and outreach language), `locationQuery` for Google Maps ("Berlin, Germany"), `tiktokRegion` ("DE"), `instagramEnabled`, `districts` (jsonb: name + postal codes, used by `fillDistricts` and the district boost in matching), `nameStopwords` (the city's own name and local generic words such as "imbiss", "lokanta"), `chainDenyList`, `stepBudgetsUsd` (jsonb per step, falling back to the defaults), `topVenues`, `cronEnabled`, `active`.
  - `CitySource` rows (city, kind: tiktok_hashtag | tiktok_search | instagram_hashtag, `value`, `enabled`, `addedAt`, `note`) replacing the arrays; the scrape reads enabled sources; `SocialPost.source` keeps the value so yield can be counted per source: a `yield` view per city (posts saved, posts with a matched mention, views, last 3 months) so dead sources are disabled from the UI.
  - `Venue.city` FK (backfill: every venue is Berlin), `PipelineRun.city`, `Report` reached through the venue; `topVenueIds`, `neighbours`, trends and the lead score scoped by city; `MonthlyPipelineCron` queues one run per active city with `cronEnabled`; the extraction and highlights prompts take the city name and language from the row; `isInCity` compares with the row's name and aliases; `normalizeVenueName` takes the city's stopwords.
  - Admin: `/admin/cities` list and detail (the form, the sources table with yield and enable toggles, budgets), a city filter on venues, posts, reports, prospects and pipeline pages, a city select on "Start a run".
  - Seed Berlin from the constants in a migration, then delete `berlin.constant.ts` and `berlin-sources.constant.ts`.
- Out: LLM-suggested sources and districts for a new city (task `city-source-suggestions`), currency and number formatting, translating the admin.
