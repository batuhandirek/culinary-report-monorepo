# Let a venue's owner sign in to a private portal with an e-mail code

## Goal
From a prospect's page the admin invites the contact e-mail; the owner gets a mail with a link, signs in by e-mail code (no password), and lands in `/portal` seeing only the venues they are a member of. Admins can open any venue's portal view.

## Why
The portal is for subscribed restaurants and nobody else; an owner should not create an account, choose a password or verify a phone. The auth module already has e-mail verification codes and sessions; what is missing is a code-only login, a venue membership, and the invite.

## Scope
- In:
  - `VenueMember` (user, venue, role `OWNER | STAFF`, `invitedBy`, `acceptedAt`), `VenueMemberService` as the one entry point (invite, accept, remove).
  - `UserRoleEnum.VENUE_OWNER` granted on first accepted membership; a `VenueAccessGuard` for `/portal/venues/:venueId/*` routes (member or admin).
  - Passwordless login: `POST /auth/login/code` (e-mail → code through `VerificationService`), `POST /auth/login/code/verify` (code → session), reusing `CredentialVerificationRequest`, throttled by the existing verification throttle constants; the invite mail (`packages/emails`) carries the portal link; the invite creates the user if none exists (no password, flagged `passwordless`).
  - Frontend: `/portal/login` (e-mail, then code: reuse `CodeStep`), `requireLogin` redirecting there for portal routes, `UserStore` knows the member venues.
- Out: the portal pages themselves (task `portal-shell-and-reports`), social login, password setting for owners.
