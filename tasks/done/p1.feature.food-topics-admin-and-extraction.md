# Edit food topics in the admin and extract mentions onto them

## Goal
`/admin/topics` lists every `FoodTopic` (label, kind, parent, aliases, Trends id or query, mention and venue counts) and the city's unmapped cuisine keys by count; an admin adds a topic, edits one, or adds an unmapped key as an alias in one click. Mention extraction is given the topic labels so new mentions use known words.

## Why
The seed covers Berlin's head; the long tail (831 keys) and new cities need mapping without a migration. Free-text cuisines from the LLM keep the tail growing.

## Scope
- In: `POST/PATCH /admin/food-topics(/:id)`, the page, a "look up Trends topic" helper (Trends autocomplete, free), the extraction prompt given the topic labels (still free text, so a new kind of food isn't forced into a wrong one).
- Out: deleting topics with data (disable instead), venue tags.

## Pointers
- `FoodTopicService`, `GET /admin/food-topics` (from `food-topics-and-topic-trends`)
- `apps/backend/src/modules/social/services/mention-extraction.service.ts`

## Acceptance
- [x] PGlite: create, edit, alias an unmapped key; the key resolves afterwards. (`food-topic.service.pglite.spec.ts`, `mention-extraction.pglite.spec.ts`)
- [x] The page lists unmapped keys and maps one. Seen on dev (Berlin): created Azerbaijani (`/m/02x6xw0`, found with the page's Trends lookup) from its unmapped row, added "cafeteria" to Lunch; unmapped went from 100 words to 44 once non-food categories were left out.
