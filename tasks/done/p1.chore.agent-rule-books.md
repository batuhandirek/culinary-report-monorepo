# Split each ingestion agent's rules from the prompt gpt-mini is coached with

## Goal
Agents A (`ReviewClaimsAgent`, `PostClaimsAgent`), B (`ClaimPartsAgent`), C (`TermTopicAgent`) and matching
(`VenueMatchAgent`) each have a **rule book** (what the right answer is, model-neutral) and a **prompt** (the
rule book plus coaching for the model that runs it: emphasis, worked examples, how a long post is cut). The
references are written from the rule book alone and their `specHash` is its hash, so coaching gpt-mini never
makes a reference stale, and changing a rule always does.

## Why
Today `instructionsFor()` is both: the reference agents get gpt-mini's whole prompt as their spec, and any
wording change marks every reference stale (`staleReferences`), whether the right answer moved or not. The
tuning loop (`ingestion-eval` skill, "Climbing a goal") needs to tell the two apart: a rule change means
re-referencing the cases it touches (`reference --force --ids`), a coaching change means nothing for Opus.

## Scope
- In: a rules constant per agent (beside `KIND_RULES` / `CHANGE_RULE`), the prompt built from it, the
  reference agents and `currentSpecs` / `specHash` reading the rules only; the skill's rule on it.
- Out: changing any rule's content; re-referencing (only the cases whose rule moves, after).

## Pointers
- `apps/backend/src/modules/evals/services/eval-reference.service.ts` (`specA`, `specB`, `specHash`)
- `apps/backend/src/modules/evals/services/eval-score.service.ts` (`currentSpecs`)

  `statements/agents/claim-parts.agent.ts`, `topics/agents/term-topic.agent.ts`, `social/agents/venue-match.agent.ts`)
