# Measure the "just opened" flag on dev's October posts and spot-check it

## Goal
We know how many of October's posts the extraction flags as a new opening and how many of ten flagged ones are false positives, and the prompt is tightened if they are many.

## Why
`Mention.isNewOpening` (shipped 2026-10-22) feeds the lead score's new-place bonus, the "New venues" filter and the Trends openings panel. Every mention extracted before then has `false`, and there is no way to re-read stored posts: `MentionExtractionService.extract` only takes posts with `analysedAt: null`, and it *adds* mentions, so clearing `analysedAt` would duplicate every mention of the post (and lose admins' corrections).

## Scope
- In: a way to re-read a sample of stored posts for the flag only, without touching their mentions: e.g. a `MentionExtractionService.reflag({ cityId, month, limit })` that runs the agent on posts with mentions and sets `isNewOpening` on the existing mention whose `venueName` matches (normalized), behind an admin route or a Data-page action; run it on dev's October posts (mini, ~1,400 tokens a post: ~1,100 posts ≈ 1.5M tokens, inside one account's daily allowance); count the flags; spot-check ten flagged posts and log the false positives; adjust the schema description or prompt if needed.
- Out: re-extracting cuisines, dishes or matches.

## Pointers
- `apps/backend/src/modules/social/services/mention-extraction.service.ts`, `apps/backend/src/modules/social/agents/mention-extraction.agent.ts`
- `apps/backend/src/modules/venues/services/venue-status-change.service.ts` (what the flag feeds)
- Tests: `apps/backend/src/modules/social/tests/mention-extraction.pglite.spec.ts`

## Acceptance
- [x] PGlite (agent mocked): the re-flag sets the flag on the matching existing mention, creates no mention and leaves an admin's correction alone.
- [x] The log gives October's flagged count and the ten spot-checked posts with the verdict on each.
