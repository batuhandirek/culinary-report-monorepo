# Topic graph: wordings are aliases + modifiers, relations are edges

## Goal
Everything people talk about is a `Topic` (a node). A wording (`Term`) points to **one main topic** (or none) with an
`exact` flag, plus optional typed modifiers (`TermModifier`) when the wording is a narrower combination not yet promoted
to its own topic ("vegan döner" → `Döner & kebab` + `has: Vegan`). Every relation between topics is a typed **edge**
(`is_a` or `has`), and the parent is one of those edge types, so "Menemen is a Turkish dish", "Menemen is a breakfast"
and "Vegan döner has Vegan" are stated once on the topic and every spelling ("menemen", "Melemen") follows. Counting
"who talked about X" walks the ancestor table (`topic_closure`). Frequent non-exact wordings promote into topics
automatically.

## Why
Today relations live on the wording (`term_topics`: term → many topics, each `same | kind_of | with`), and the tree on
`topics.parent_id`. A relation has to be repeated on every spelling of a thing: "menemen" is Menemen (same) and
Breakfast (kind of), but "Melemen", also Menemen, misses Breakfast unless someone links it again. And a topic can't
relate to anything but its one parent. Moving topic relations into `topic_edges` and keeping only unpromoted modifiers
on `term_modifiers` fixes both without losing long-tail modifier counts ("gluten-free menemen" still counts for
Gluten-free) and without exploding the graph into thousands of 1-mention topics. Nothing is released (root
`CLAUDE.md`): the shape can break.

## The model

| Thing | Shape |
|---|---|
| `Topic` (node) | `key` (fixed at creation), `label`, `kind` (`cuisine`, `dish`, `drink`, `diet`, `format`, `meal`, `ingredient`, `aspect`), `hint`, `embedding` (for shortlist retrieval), Trends fields, `discoveredAt`. **No `parent` column.** |
| `TopicEdge` (new, `topic_edges`) | `from` (the topic it is about), `to`, `type` (`is_a` \| `has`), `rank` (order among one topic's edges of a type), `decidedBy` (`seed`, `match`, `ai`, `admin`), `decidedAt`. Unique (`from`, `to`, `type`). Cascades with either topic. |
| Edge types | `is_a`: `from` is a kind of `to` (Ramen → Japanese, Queue → Waiting, Menemen → Turkish, Menemen → Breakfast); counts in strict and broad modes. `has`: `from` has `to` as a diet, ingredient or attribute (Vegan döner → Vegan, Chicken döner → Chicken); counts in broad mode only. Default type comes from `to.kind`: `cuisine`, `meal`, `format`, `dish`, `drink` → `is_a`; `diet`, `ingredient` → `has` (an admin may override for dish-to-dish cases like "döner with fries"). |
| `Term` (wording) | `key` (folds accents and plurals), `name` as said, **`topic`** (one, nullable FK), **`exact`** (boolean, default `false`: `true` = synonym of `topic`, `false` = narrower concept under `topic`), **`proposedLabel`** / **`proposedKind`** (nullable: the label and kind agent C gives a non-exact wording as a topic of its own), `decidedBy` / `decidedAt`. Decided with `topic = null` and no modifiers = not food/aspect ("food", "plate"). **`term_topics` and `TermTopic` go.** |
| `TermModifier` (new, `term_modifiers`) | `term` (FK `terms`, cascade), `topic` (FK `topics`, cascade), `type` (`is_a` \| `has`), `rank` (int). Primary key (`term`, `topic`). Holds a non-exact wording's extra `is_a` links (518 wordings today) and `has` modifiers (`Vegan`, `Chicken`) until promotion moves them onto a dedicated topic. Empty when `term.exact = true`. |
| `topic_closure` (derived) | (`topic`, `ancestor`, `depth`, `hasEdge`): every topic with each topic it counts for through `is_a` and `has` edges, itself at depth 0 (`hasEdge = false` if at least one pure `is_a` path reaches `ancestor`). Rebuilt by `TopicService` whenever a topic or edge changes, in the same transaction. ~361–1,300 topics, so a full rebuild is cheap. |

Rules:
- **Counting:** a wording evokes its `term.topic` (as `is_a`) plus any `term_modifiers` (with their `type`). Each evoked
  topic expands through `topic_closure`. "Strict" counting ignores `has` modifiers (`term_modifiers.type = 'is_a'`) and
  filters `topic_closure.hasEdge = false`; default (broad) counting follows both. Count distinct statements/sources per
  ancestor so multiple paths or multiple terms in one claim never double count.
- **Food `is_a` may have several targets.** The one ranked first (`rank = 0`) is the topic's **display parent**: the
  tree, "Dish under Turkish", and the rating benchmark's walk up to a bigger topic all use it. A topic shows under each
  of its `is_a` parents in the tree pickers, like a shortcut.
- **Aspects:** `kind = 'aspect'`. Root aspect = no outgoing `is_a` edge. Child aspect = one `is_a` edge at most (its
  root), no `has` edges. That keeps the labeller's root logic, the aspect pages and the two-level readers valid;
  enforce it in `TopicService`. A wording whose `term.topic` is an aspect has `exact = true` and no modifiers.
- **Edges stay on one side:** food to food, aspect to aspect; no cycles (`TopicService` refuses both, 400).
- **Admin's word stays final:** the AI never changes a term or edge where `decidedBy = 'admin'`.

## Wordings under the new model (agent C & promotion)
- **Name match unchanged:** a wording whose normalized form is a topic's key or label gets `topic = that topic`,
  `exact = true`, `decidedBy = 'match'`, with no LLM.
- **Shortlist before Agent C:** embed the wording and pass Agent C:
  1. All topics in the small fixed groups (`cuisine`, `diet`, `meal`, `format` — ~83 topics) plus all aspect roots;
  2. The top ~20 closest `dish`, `drink`, `ingredient` and child `aspect` topics by embedding similarity.
- **Agent C (`TermTopicAgent`) answers one of three, one wording a call:**
  - `{ topic: key, exact: true }`: same thing as an existing topic ("Melemen" → Menemen, "Pommes" → Fries, "türkisches
    Essen" → Turkish, "waiting time" → Waiting);
  - `{ none: true }`: not food, drink or aspect (`topic = null`, `exact = false`, no modifiers);
  - `{ topic: key | null, exact: false, label?: string, kind?: TopicKind, modifiers?: { topic: key, type?: 'is_a' | 'has' }[] }`: a
    narrower concept or combination, with the label and the kind it would have as a topic of its own (stored as
    `proposedLabel` / `proposedKind`) ("kumpir" → `topic: turkish, exact: false`; "Turkish grilled sandwiches" →
    `topic: turkish, exact: false, label: "Turkish sandwich"`; "vegan döner" → `topic: doner-kebab, exact: false,
    label: "Vegan döner", modifiers: [{ topic: vegan, type: 'has' }]`). Edge `type` defaults from the target's `kind`
    when omitted.
- **Canonical label for combinations:** agent C gives one `label` per thing whatever the spelling or language ("vegan
  döner", "veganer döner" → "Vegan döner"), so variants share one promotion key.
- **Promotion is code, no LLM:** runs after each `terms` backlog batch and in relink.
  - Considers all wordings where `exact = false` and `topic` is not an aspect.
  - Groups them by the folded key (`termKey()`) of `COALESCE(proposedLabel, name)`.
  - When a group reaches `MIN_TOPIC_USES` (15) across `MIN_TOPIC_SOURCES` (5):
    1. **A topic with that name already exists** (by `TopicService`'s key of the label, or a label match): no new topic;
       the group's wordings move onto the existing one (step 4). Never a twin.
    2. Otherwise creates the `Topic` through `TopicService.create` (the one entry point, which keys and checks it):
       `label` = the most-used wording's `proposedLabel`, else its name capitalized; `kind` = the most common
       `proposedKind` in the group, else the first `dish`/`drink`/`ingredient` kind among its `is_a` targets, else `dish`.
    3. Its edges, `decidedBy: 'ai'`. Edges go on a topic only when true for every one of it, whatever the spelling:
       - **`is_a`: every one the group's wordings carry** (their `term.topic` and `is_a` modifiers): what a thing is
         doesn't change with its spelling ("kumpir" → Turkish, "Kumpir" → Street food: Kumpir is_a both). The most-used
         wording's main topic is rank 0, the display parent.
       - **`has`: only one carried by most of the group's uses** (Kumpir has Potato). A `has` only some wordings carry
         describes those orders, not the dish ("kumpir mit Käse" has Cheese; "vegan kumpir" has Vegan) and stays on
         those wordings as a modifier.
    4. Every AI-decided wording in the group, and an `admin`-decided one whose `(topic, modifiers)` the new topic's edges
       cover, moves onto the topic: `term.topic` = it, `exact = true` when it has no modifier left beyond the topic's
       edges (else `exact = false` keeping the rest: "kumpir mit Käse" → Kumpir + has Cheese), `decidedBy` kept.
- **Agent D (`TopicDiscoveryAgent`, the `topic-discovery` backlog) is removed:** Agent C + the promotion step do its job.
- **Admin API:** `PATCH /admin/terms/:id` sets `{ topicKey, exact, modifiers }` or `{ auto: true }`, and an admin can
  still click "Make it a topic of its own" to promote a wording immediately regardless of floor.

## Carrying the dev data (the user, 2026-11-10: convert with the LLM rather than hand rules)
In one change: schema, then a mechanical step, then an LLM pass over everything else.
1. **Mechanical, no LLM:**
   - each `topics.parent_id` becomes an `is_a` edge in `topic_edges`, rank 0, `decidedBy: seed`; drop the column;
   - a wording whose only link is one `same` link becomes `topic` = that topic, `exact = true`, keeping its
     `decidedBy`.
2. **LLM pass:** agent C, under its new contract, is asked again about every other decided wording.
   - About 8,300 wordings: no `same` link (7,869), a `same` link plus others (373), several `same` links (44), aspect and
     food links at once (29).
   - Each call gets the wording, its shortlist (as live) and **its current links with their relations as a hint**.
   - An `admin` decision is converted the same way and keeps `decidedBy: admin`; review the 1 admin term by hand.
   - It runs as a hand-started command (`llmPaid`, the eval's kind of run): on Haiku about $3 and under an hour (~$0.0003
     a wording), or on the OpenAI allowance (free, over a few nights, competing with the reading).
   - A wording the pass couldn't answer keeps its old main link as `topic`, `exact = false`, and is logged.
3. Decided terms with no links ("none") keep `topic = null`, `exact = false`, `decidedBy` unchanged. Undecided terms
   (14,598) stay undecided; the `terms` backlog decides them under the new contract.
4. Drop `term_topics`. Build `topic_closure`. Embed every topic (`Topic.embedding`) for the shortlist.
5. Run the promotion job once: frequent narrower wordings (`kumpir` with 27 uses, `vegan döner`) become topics.
6. Record before/after in the log: topics and edges by type; and for Turkish, Döner & kebab, Vegan, Breakfast, Waiting
   and Price, Explore's source counts for October 2026 in Berlin.
