# Plain ids to foreign keys

## Goal
Three references the database can't see become real links, so they're joinable, indexed, and cleaned up when the row they point at goes away.

## Why
- **`ApifyRun.pipelineRunId`** (text) names the `PipelineRun` that started a paid run. As a plain value, "what did this pipeline run cost" can't use a join or an index, and a deleted run leaves a dangling id.
- **`Brand.excludedVenueIds`** (jsonb `string[]`): places an admin said aren't this brand's branches. A merged or deleted venue stays in the list forever, and "which brands excluded this venue" needs `jsonb_array_elements`.
- **`SocialAccount.rejectedBrandIds`** (jsonb `string[]`): brands an admin said an account isn't. Same problems. `brand.service.ts` already queries it with `jsonb_array_elements_text` (~line 629) when brands merge.
- Nothing is released, so the shapes change freely. Only dev data has to come across.

## Design
- `ApifyRun.pipelineRun` → `PipelineRun` (nullable, `set null`, indexed) in place of `pipelineRunId`. `stepKey` stays text: it is a step name, not a row. `apifyRunContext` (`apify/util/apify-run-context.ts`) carries the id as now and the service sets the relation.
- `BrandExcludedVenue` (`brand_excluded_venues`): `brand` (cascade), `venue` (cascade), unique pair, `createdAt`. It replaces `Brand.excludedVenueIds`. On a brand merge, the merging code moves its rows (check `BrandService` merge for where the list is combined today).
- `AccountRejectedBrand` (`account_rejected_brands`): `account` (cascade), `brand` (cascade), unique pair. It replaces `SocialAccount.rejectedBrandIds`. On a brand merge, the rows move to the surviving brand (today's `jsonb_array_elements_text` update in `brand.service.ts`).
- Data move: these are generated migrations, so copy the dev data with a one-off service method or the house pattern in the `backend-entity` skill, then drop the old columns.

## Scope
- In: the three changes, every reader and writer, tests, `ENTITIES.md`, the skill where it names these fields.
- Out: `Mention.city` (the city name the LLM read, kept as raw text: the post has the real `city` link, and the text is what flags a mention as `OTHER_CITY`). `FsmStateChange.ownerType/ownerId` (polymorphic by design; no machine uses the engine).
