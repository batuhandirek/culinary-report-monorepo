# Term eval on the topic graph

## Goal
`npm run eval -- reference|run --kind term` work again: each of the ~500 term cases has an Opus reference in agent
C's current contract (one main topic or none, `exact`, modifiers with `is_a` / `has`, a proposed label and kind for a
narrower wording), and a run scores agent C against it.

## Why
Agent C decides every wording the city uses, and its answers decide what counts for what. Since the topic graph its
answers are judged only by reading them; the converter's run (6,329 wordings on Haiku, 2026-11-10) showed misses
("antipasti", "beelitzer spargel" as not food; "Carrot cake is a kind of vegetable kebab") that a scored run would
catch before a prompt or model change ships.

## Scope
- In: the reference agent's spec and schema (`evals/agents/term-reference.agent.ts`), the term cases' stored shape
  (`evals/interfaces/eval-case.interface.ts`: drop the legacy `TermRelation`), collect / reference / run / score for
  terms, the report's term section, the skill.
- Out: the review and post parts (unchanged).
