# Decide the report's language per venue (German for Berlin owners?)

## Goal
A recorded decision on which language a venue's report is written in, and a follow-up task if it is not "English only".

## Why
The highlights agent writes English and every label in `ReportView` is English, while the prospects are Berlin Imbisse, Döner and chicken places, cafés and bakeries whose owners mostly read German (several have no website). An English report is a friction at the exact moment of the pitch. The outreach module already keeps a `language` per prospect for its e-mails; the report sent with that e-mail should match.

## Options
1. English only (today).
2. German for every report.
3. Per venue: the report follows `Prospect.language` (default `de` for the Berlin pipeline when no prospect exists). The highlights agent gets the language in its instructions; `ReportView` labels come from a small dictionary keyed by language; review excerpts keep the review's language (today `textTranslated` is English because the scrape asks for `language: 'en'`: scrape with `de`, or keep both).

## Assumption if unanswered
Option 3, with the LLM output checked on two dev reports before the default flips to `de`.

## Acceptance
- [ ] Decision in the log; follow-up task written (`report-language-per-venue`) naming the places that change: `report-highlights.agent.ts`, `review-analysis.agent.ts` ("short English phrases"), `review.service.ts` (scrape language), `ReportView.svelte`, `lib/culinary.ts` labels, `Prospect.language`.
