# Read posts and reviews as one durable workflow per item

## Goal
`IngestionWorkflows.ingestCity` fans out: one child workflow per unread post (`readPost(postId)`: gate → claims → venue match → labels, each agent call its own `LlmWorkflows.generate` child through `DurableLlmService.generate`, which waits for an account) and per unread review, on an `llm` queue whose `rateLimit` is the roster's cap, so a post that waits for the allowance never holds the other 499 back, a resume never re-asks a finished agent, and the ledger shows each post's cost.

## Why
Today a pass is one step (`ingestionService.ingestCity`) running `MentionExtractionService.extract` over batches of 1,000 with `runPool`; a model refusing mid-batch ends the pass and the batch's half-read posts are read again next hour. Per-item workflows give exactly-once reading per item, durable waits per item (`DurableLlmService`), and a spend row per post with the workflow id.

## Scope
- In: `readPost(postId)` and `readReview(reviewId)` workflows; the per-post reading services split into steps the workflow calls (gate, agent A, matching, labels) rather than batch loops; `ingestCity` lists the unread ids in a step and `start`s the children with `workflowId: ingest-post-v1-${postId}` (idempotent across hourly runs) on an `llm` queue with `workerConcurrency` and `rateLimit` from the roster (OpenRouter's 20 a minute when it serves); `DurableLlmService.generate` for every agent call; the eval (`ingestion-eval` skill) run before and after, as the inputs and post-processing move.
- Out: the pipeline runs (`pipeline-runs-as-workflows`), the admin page.

## Acceptance
- [ ] A post whose agent call hits the allowance leaves its workflow sleeping until the reset while the other posts finish (PGlite suite with `durable: true`, a fake agent).
- [ ] The hourly run enqueues no second workflow for a post already in flight (`workflowId` idempotency).
- [ ] The eval's scores do not drop; `llm_calls` rows carry the post's workflow id.
