# Let handle-keyed sources follow an account's rename

## Goal
When a scrape sees an account under a new handle (`SocialAccountService.ensure` renames it and stores a `SocialAccountHandleChange`), the places that name the account by its handle text follow it: a city's creator source (`CitySource` kind `tiktok_account` / `instagram_account`, `value` the handle) and outreach's `Prospect.instagram`.

## Why
The account row follows its user id now, but these store the handle itself. After a rename, the watched creator's source asks the profile scraper for a handle that is gone (or now someone else's), and outreach links the wrong profile. The profile scrape takes handles only, so the source has to carry the new one.

## Scope
- In: on a rename, update the matching creator sources (through `CityService`, which owns them; `PostSource.value` keeps the old handle as found) and the prospect's handle (through `OutreachService`), or flag them on Today for an admin; on a handle taken by someone else, flag rather than move.
- Out: re-keying stored `PostSource` rows.

## Pointers
- `apps/backend/src/modules/social/services/social-account.service.ts` (`renameTo`, `loseHandle`, `absorb`)
- `apps/backend/src/modules/pipeline/services/account-watch.service.ts` (the watch list reads sources by handle)
- Social imports no outreach module and cities owns sources: a persisted event on the rename is the likely seam.

## Acceptance
- [ ] A creator source whose account renamed scrapes the new handle in the next run.
- [ ] A prospect whose Instagram renamed shows the new handle.
