# Let an admin correct a claim from Explore

## Goal
On a claim in the Explore page's table (`ClaimsTable` with `explore`), an admin can say "not a claim" and "the aspect
is …" (a picker over the aspect tree). The word is final, like a mention's correction: agent B never overwrites it,
a re-read of the source keeps it on the claim it re-creates with the same text, or drops that claim for "not a
claim", and every reader counts it at once. Corrections are what `claims-eval-set` / the ingestion eval can import
as reference cases.

## Why
Explore shows every claim behind a count; when one is wrong (a claim that is no claim, a wrong aspect) the admin
sees it there and should fix it there, rather than wait for a prompt change and a paid re-read. The brief's
acceptance: "corrected by an admin, and the correction moves every statement using it" (wordings already can, on the
Terms tab; claims can't yet).

## Scope
- In: the stored correction (fields on `Statement`, e.g. `dismissedAt` / `correctedBy` / `correctedAt`, or an admin
  aspect part marked admin: decide in the design), its one writer (`StatementService`), `StatementPartsService`
  keeping an admin aspect part when B reads the claim again, the re-reads (`ReviewService.reread`,
  `MentionExtractionService.reread`, `replaceForReview` / `replaceForPost`) carrying a correction across by the
  claim's text (or dropping a dismissed claim), every reader leaving dismissed claims out (theme counts, reports,
  Explore, clusters, landing, the Claims tables: one SQL predicate next to `judgingSql`), the row actions in
  `ClaimsTable`, PGlite tests.
- Out: correcting a claim's text, sentiment or kind (decide in the design whether kind belongs in); correcting
  food wordings (the Terms tab does it, by term).

## Acceptance
- [ ] "Not a claim" on a claim removes it from Explore's counts, the Praise and complaints tab and a rebuilt report.
- [ ] "The aspect is X" moves the claim to X in every reader at once; B's next read of the claim keeps X.
- [ ] A re-read of the source keeps both corrections on a claim with the same text (PGlite).
- [ ] The eval can list the corrections as reference cases (or a task says how).

## Open questions
- Should "not a claim" delete the row (and a re-read skip that text) or keep it flagged? Assumption: keep it flagged
  (`dismissedAt`), so it can be undone and the eval can read it.
