# Remove the topic relinking import after the deploy

## Goal
Once production has booted with `Migration20261110192102_topic_graph` and logged
`Topic relinking (…): N of N applied`, the folder, the import, the converter and their rule are gone from the repo.

## Why
They exist only to carry the old term × topic links across once. Left in, every boot reads a 1.6 MB file and applies
nothing, and the converter reads tables that no longer exist.

## Scope
- In: `tmp/topic-relinking/` (the folder), `topics/services/topic-relinking-import.service.ts` (and its registration in
  `topics.module.ts`), `topics/services/topic-relinking-convert.service.ts`, `topics/topic-relinking.module.ts`,
  `topics/topic-relinking.cli.ts`, `topics/constants/topic-relinking.constant.ts`,
  `topics/interfaces/topic-relinking.interface.ts`, `topics/util/topic-relinking-file.ts`, the import's case in
  `topics/tests/topic-graph.pglite.spec.ts`, the root `topic-relinking` script, the rule "The old term × topic links were
  converted once" in `domain-venues-and-reports`, and `tasks/done/p1.feature.topic-graph.md`.
- Out: the migration itself (generated history, never edited).

## Pointers
- Production's boot log: the `TopicRelinkingImportService` line (applied, left alone, unknown topics, promoted).
- Before deleting, check production's `topics` count rose by the promoted topics and `term_modifiers` is filled.

## Acceptance
- [ ] Production's log shows the import applied (paste the line in the log below).
- [ ] The files above are gone, `npm run backend:test` passes, the skill has no word of the relinking.
