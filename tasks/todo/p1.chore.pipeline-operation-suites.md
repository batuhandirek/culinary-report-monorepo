# Port the commented-out pipeline suites to the operation workflows

## Goal
The behaviour the old `PipelineService` suites asserted (which venues each step scrapes, the review backfill split, a chain's branches, the delivery and details sets, the demand samples' order, the review watch) is asserted again against the operations that do it now, and the creator watch list's suite runs against `social`'s `AccountWatchService`.

## Why
Those suites were the only check that each step takes the right venues and budgets; they are commented out (the repo's convention while the tests are left alone), so a wrong venue set would go unnoticed until it costs money on Apify.

## Scope
- In: `pipeline/tests/{pipeline-delivery,pipeline-fill-competitors,pipeline-per-branch,pipeline-refresh-details,pipeline-reviews,pipeline-search-interest,pipeline-top-venues,demand-sample,review-watch}.pglite.spec.ts` rewritten against the operation's workflow (its steps run plainly, the facade faked as `read-reviews/tests/read-reviews.workflow.pglite.spec.ts` does) or, better, the domain method now holding the logic (`ReviewService.planReportMonth`, `VenueReservationService.sampleOrder`, `ReportBrandsService.of` / `scope`); `pipeline/tests/account-watch.pglite.spec.ts` and `read-mentioned-profiles.pglite.spec.ts` moved next to their code and uncommented; a suite for `runOperation`'s one-id rule (a dependency started by two callers runs once).
- Out: a real-DBOS suite (`describeWithDbos`) for the whole dependency chain.

## Pointers
- `apps/backend/src/modules/pipeline/tests/` (the commented suites)
