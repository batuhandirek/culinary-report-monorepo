# Feedback theme discovery with embeddings

## Goal
The `*_other` tail of the themed points (and, on request, any theme's details) is clustered by meaning each month, per city and topic; a cluster of 5+ details from 3+ venues is shown on an admin "Unrecognised themes" tab with its sample details, counts and a suggested label, so the vocabulary grows from what guests actually say instead of guesses. Inside a report, the sample details shown for a topic are de-duplicated by meaning, so the five quotes are not "expensive", "pricey" and "quite expensive".

## Why
- A fixed vocabulary (`feedback-themes`) keeps counts comparable but cannot know next year's theme ("tip prompts on the terminal" appeared in 2024; "açai bowl availability" is on dev today). The dev tail after the backfill shows what the list missed.
- The infrastructure is in place and unused: `EmbeddingsModule` (`text-embedding-3-large`, 3072-dim `halfvec`, `pgvector` in Docker and in PGlite) with account rotation; nothing calls it today.
- Embeddings are not the counting layer: clusters move month to month and a count that changes when it is recomputed cannot be quoted as "6 of 34 reviews". They are the discovery layer, like the Unrecognised words tab for food topics.

## Design
- `social/services/feedback-theme-discovery.service.ts`: `clusters(cityId, month, { theme?: string | 'other' })`: loads the month's points (reviews of the city's venues, mentions by others), embeds each distinct detail with `EmbeddingsService.embedUncached` (~10 tokens each; cents a month), clusters within a topic greedily by cosine against running centroids (threshold ~0.80; a pure `util/cluster.ts` with a test on a hand-made set), keeps clusters with 5+ details from 3+ brands, and asks `ThemeSuggestionAgent` (mini) once per cluster for a label of ≤ 4 words and the closest existing theme or "new". Nothing is stored: a cluster is recomputed on request (a month has a few thousand details; keep an in-memory LRU per city and month).
- `GET /admin/feedback-themes/suggestions?cityId=&month=` and a tab on `/admin/trends` under Themes: cluster label, count, brands, samples; "Add as theme" copies the key and hint to the clipboard (the vocabulary is code: adding a theme is a commit, then the backfill runs again for the `*_other` points).
- Report quotes: `sampleDetails` in `ReportView` takes one detail per cluster; done at build time (`praiseDetails` / `complaintDetails` get a `cluster` index) so the view stays pure.
- Prior art: BERTopic (embeddings → UMAP → HDBSCAN → c-TF-IDF labels); here the LLM labels and the clustering is greedy, since the sets are small.

## Scope
- In: the above.
- Out: storing vectors (an `Embedding` cache row per detail would be dead weight: details repeat rarely); automatic vocabulary changes; clustering across cities.

## Acceptance
- [ ] Pure: the clustering groups paraphrases ("prices went up", "prices have become too high", "dürüm now €9.50") and keeps "cash only" apart, on fixed vectors.
- [ ] PGlite: clusters for a month, with the floors, the embedder mocked.
- [ ] The tab lists clusters for Berlin, September 2026.

## Open questions
- Threshold and floors. Assumption: 0.80 cosine, 5 details, 3 brands; tune on dev.
