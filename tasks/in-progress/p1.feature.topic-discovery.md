# Topic discovery

## Decisions (the user, 2026-10-31)
1. **Strength lives on the term → topic link** (`TermTopic.relation`): `same` ("Pommes" → Fries: the same thing, a
   spelling, a translation), `kind_of` ("Garlic Parmesan Fries" → Fries: a more specific kind), `with` ("vegan döner"
   → Vegan, "chicken döner" → Chicken: an attribute or an ingredient). Analysis picks a strength: strict (same),
   normal (same + kind_of), broad (all; today's behaviour, the default). "Weak" child topics (few sources) are a
   volume threshold when read, never stored.
2. **Discovery creates topics live**, under a parent so nothing is lost (a child counts for its parent), stamped
   `Topic.discoveredAt` for provenance; no review page ("I doubt we need to be able to edit them").
3. Built here; every LLM spend on real data asked first.

## Findings that motivate it (dev Berlin, 2026-10-31)
- 39% of food parts (11,279 of 28,967) link to no topic: generic words that should be no food part ("food" 790,
  "drinks", "dishes", "meal", "plate", "snacks", "toppings"); ingredients with no topic kind ("meat" 468, beef, cheese,
  rice, eggs, vegetables, mushrooms, avocado, chocolate, tomatoes); dishes and drinks with no topic (waffles 70, pickles
  60, pork knuckle 42, French toast 35, meatballs incl. Königsberger Klopse, wraps, fritters, stews, halloumi, sauces /
  garlic sauce, soft drinks, lemonade, smoothies, ayran).
- Coarse topics lump distinct dishes: Döner & kebab (372 wordings, ~3k uses: dürüm, Gemüse kebab / vegetable kebab /
  vegetable döner), Burgers (cheeseburger, smash burger / smashburger), Chicken (half / grilled / rotisserie chicken),
  Sandwiches (sando), Cake (cheesecake), Noodles (hand-pulled, Biang Biang, udon), Bread (sourdough, flatbread), Seafood
  (oysters, shrimp, salmon, mussels).
- Wrong links from the first agent C pass: duck → Seafood, manakish → Pizza; compounds with one link only ("vegan
  döner" → Döner & kebab, no Vegan); "breakfast", "brunch", "lunch" linked to nothing though the topics exist (decided
  by the old dish-name agent, which was only offered dishes and drinks; the name match never ran on them again).

## Design
- **Schema:** `TopicKindEnum.INGREDIENT`; `Topic.discoveredAt`; `TermTopic.relation` (`same` | `kind_of` | `with`; existing
  links: a name match's and an admin's `same`, an agent's `kind_of` until re-asked); `Term.groupedAt` (when discovery
  last looked at the wording).
- **Agent C** (`TermTopicAgent`) answers each topic with its relation, is offered every kind incl. ingredients, and
  answers "none" for generic words. **Agent B** (`ClaimPartsAgent`) never answers a generic word as a food.
- **The exact-name rule always wins** over an agent's answer (not only after a topic change): a wording that is a
  topic's key or label as a whole is linked to it, `same`.
- **Discovery** (`TopicDiscoveryService`, `TopicDiscoveryAgent` on mini; the backlog `topic-discovery`, after `terms`):
  candidates are decided wordings with enough use (claim parts, distinct sources) that link to no topic or only
  `kind_of` / `with`, not grouped yet (`groupedAt` null); ~200 a call with the food legend (key, label, kind, parent);
  the agent groups them into new topics (label, kind, parent key, the wordings and each one's relation) or says a
  group belongs to an existing topic; code checks the floors (uses and sources per new topic), the parent and the
  kind, creates the topic (`TopicService.create`, `discoveredAt`), links the wordings, stamps `groupedAt`, and queues
  the re-link. An existing key or label is linked, never duplicated.
- **Readers:** `FOODS_SQL` and the terms' topics take a strength (default broad); the Explore task exposes it.
