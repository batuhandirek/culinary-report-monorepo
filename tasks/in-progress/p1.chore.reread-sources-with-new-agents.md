# Re-read the stored sources with the new agents

**Read first**: the brief `statements-and-concepts` (decision 8), the root `CLAUDE.md`'s "proof of concept" rule,
then this. Needs `statements` done. Program order: `topics-tree` → `terms` → `statements` →
**reread-sources-with-new-agents** → `google-tags-as-statements` → `talked-about-pages`.

## Goal
Every stored review, post and blog article has statements read by agents A and B (neutral facts, city claims,
every claim's parts), not only the sources analysed after `statements` shipped. Reviews are re-analysed (their
statements replaced); posts and articles are re-read **additively**: A's places are paired with the stored mentions
by name (as `MentionExtractionService.reflagOpenings` pairs), their claims replace the mention's statements, the
post's city claims are written, and no mention is added, removed or re-matched; a `manual` or `ignored` mention
keeps its correction. The user is asked for the spend first, with the estimate.

## Why
The user (2026-10-29): "Reread for sure … this is a POC … prompt me to spend some money to get the data to where
it deserves". Migrated rows carry no neutral facts and no city claims, and their parts were read by the old
prompts. Posts' mentions must never be recreated (matches and admin corrections would go).

## Scope
- In: a `reread-reviews` and a `reread-posts` LLM backlog (`modules/backlog`), or the same as admin-started runs
  within the nightly budget; the pairing rule; the estimate; the run on dev Berlin; the before/after numbers.
- Out: new sources (comments, press), Google tags (`google-tags-as-statements`), anything the new agents don't
  already do.

## Order of work
1. The estimate, in the log and to the user before anything runs. Dev Berlin: 7,173 analysed reviews (A in batches
   of 10 → ~720 calls; B over ~22k claims → ~220 calls), 5,146 posts and articles (A one call each, ~3k tokens with
   the legend-free prompt → ~15M tokens, two to three nights of the 3M nightly backlog budget across accounts
   unless the budget is raised for the run; B over ~19k claims → ~190 calls). Measure A's and B's real per-call
   usage on 50 sources first (`BacklogRun.tokens`), then put the number to the user.
2. `ReviewService.reanalyse` → the existing `analyse` path over `analysedAt` before the `statements` ship date
   (a parameter, not a constant), as the backlog `reread-reviews` (priority 40; a batch = 500 reviews); each review's
   statements replaced; `analysedAt` restamped.
3. `MentionExtractionService.reread` (the additive pass): A over the post; pair each answered place with a stored
   mention of the same `normalizeVenueName` (one left on each side pairs too, as `reflagOpenings`); replace the
   paired mention's statements with the place's claims; write the post's city claims; an answered place with no
   stored mention is **not** added (logged as `unpaired`), a stored mention A didn't answer keeps its statements;
   `isNewOpening`, `visited`, `summary`, `sentiment` may be refreshed from A (they are the mention's own reading,
   not its match); `matchStatus`, `brand`, `venue`, `manual`, `ignored`, `matchNote` never touched. The backlog
   `reread-posts` (priority 45; a batch = 200 posts, most viewed first), `rereadAt` on the post.
4. B runs as its own backlog over the new claims (already `statement-parts`); C over new wordings (`terms`).
5. Tests: `mention-reread.pglite.spec.ts` (pairing by name and the one-each fallback, an unpaired place not added, a
   manual mention keeping its correction, city claims written, statements replaced on the paired mention only, the
   backlog), `review-reread.pglite.spec.ts` (replacement, restamp, the window).
6. Run on dev after the user's yes; write the before/after numbers (statements, neutral, city claims, mentions
   unchanged) in the log; the skill's "never re-extract posts" rule gains the additive re-read as the one way.
