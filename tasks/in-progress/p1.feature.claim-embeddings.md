# Claim embeddings: search by meaning and missing aspects

## Goal
Every claim with text (`Statement.text`) has a 1024-dimension vector of its own. On top of it: (1) the Claims tables
(Trends, a brand, a branch) can be searched by meaning ("cold food" finds "the fries arrived lukewarm"); (2) a Trends
tab "Missing aspects" clusters a city's claims that no aspect fits (no aspect part, or filed at a root only) and shows
each cluster with a suggested label, its count, brands and samples, so an admin creates the aspect from it.

## Why
- 12% of claims have no aspect and many more sit at a root (`food`, `price`, `other`) because no finer aspect fits.
  Clustering them shows what the tree misses ("music too loud", "dog-friendly", "overrated", "loyalty card"). Aspects
  are rows now (`Topic` kind `aspect`), so a found one is created in the admin topic dialog, no commit, and agent B
  files into it on its next read.
- The text search of the Claims tables matches words only.
- Embeddings are a discovery and search layer, never a counting layer: a cluster moves when recomputed, so no count
  a report quotes ever comes from one.

## Design
- **Storage:** `Statement.embedding` (`HalfvecType`, length 1024, nullable, `hidden: true`, never in a DTO) and
  `embeddedAt`. A vector belongs to its row: a claim's text never changes (a re-read writes new rows; a deleted
  source cascades), so nothing goes stale. An HNSW index on `embedding halfvec_cosine_ops` for search, hand-written if
  the generator can't express it (see `backend-entity`: halfvec quirks; PGlite has pgvector).
- **Embedding:** `text-embedding-3-large` with OpenAI's `dimensions: 1024` (Matryoshka; at 1024 it still ranks above
  the small model at 1536). Extend `EmbeddingsService` with a batch method that takes the dimensions, e.g.
  `embedManyUncached(values: string[], { dimensions: 1024 })`, through `OpenAIAccountsService.run` as `embed` does (never
  a key by hand). Find out how Mastra's `ModelRouterEmbeddingModel.doEmbed` forwards provider options (`providerOptions:
  { openai: { dimensions } }` in the AI SDK) and assert the returned length is 1024. Up to ~1,000 claims a request.
- **Filling:** an `LlmBacklog` registered by the statements module, key `statement-embeddings`, priority 60 (after the
  re-reads), a batch = 2,000 claims with text and no `embeddedAt`, most recent month first; `tokens` from the
  response's usage. New claims get theirs the next night (no step in the pipeline).
- **Search:** `GET /admin/statements` gains `like` (a phrase): the phrase is embedded once (the `Embedding` cache row
  is fine for it, `getEmbeddings`, but at 1024 dimensions: check the cache's fixed 3072 column, or embed uncached),
  and the page is ordered by cosine distance instead of newest first, with every other filter applied; claims without
  a vector are left out of a `like` search and the page says how many are not embedded yet. In `ClaimsTable.svelte` a
  "Similar to…" text filter next to the word search.
- **Missing aspects:** `StatementClusterService.clusters({ cityId, month | quarter, root? })`: the scope's claims with
  text and a vector that have no aspect part or whose aspect is a root (`TopicIndex.isRoot`), own posts out, clustered
  by a pure greedy cosine clustering against running centroids (`statements/util/cluster.ts`, threshold ~0.82, tuned on
  dev), kept at 5+ claims from 3+ sources of 2+ brands (or the city: a city claim counts as its own brand), largest
  first, then one mini call per cluster (`AspectSuggestionAgent`: a label of ≤ 4 words, a one-line hint, the root it
  belongs under, or "fits <existing aspect key>" when B should have filed it). Nothing stored; an in-memory LRU per
  scope. `GET /admin/statements/clusters?cityId=&month=&root=` and a Trends tab "Missing aspects": each cluster's label,
  hint, root, count, brands, 5 samples (one per sub-cluster, so not five paraphrases), "Create aspect" opening
  `TopicFormDialog` filled (kind aspect, parent, label, hint), and "See claims" opening the Claims tab with `like` set.
- **Cost, asked first:** dev Berlin holds ~60k claims at ~15 tokens: ~1M tokens, ~$0.13 at the list price of
  `text-embedding-3-large`; check whether embeddings fall under the accounts' complimentary allowance. The backlog's
  first drain is a spend: put the estimate to the user and wait for the yes (root `CLAUDE.md`, POC rule) before the
  first batch runs; the skill's "never paid per call" line for backlogs must be squared with it (state the decision).
- **Timing:** the post claims are about to be rewritten by the re-read (`reread-posts`, task
  `reread-sources-with-new-agents`): build now, but don't run the backfill before that backlog is empty, or the vectors
  of ~30k post claims are paid for and deleted the same night.

## Scope
- In: the above, with PGlite tests and the skill.
- Out: embedding sources (reviews, posts) or terms; using vectors to file aspects or sentiment (agent B does that);
  grouping a report's quotes by meaning (a later task once clusters prove themselves); cross-city clusters.
