# SEO and SSR

## Map

Root `+layout.ts` sets `ssr = false`. Routes: `(landing)` (the home page `/`, SSR'd: the city's newest published live edition (`GET /landing/:citySlug`, `domain-venues-and-reports`), its newest published month and quarter found through the sitemap's `highlights` / `foodtrends` sections for its links, the newest three blog articles; each part fails on its own into the page's "being counted" state; the only title that leads with the brand), `newsletter/confirm` and `newsletter/unsubscribe` (client-rendered, `noindex`), `auth/`, `(admin)`, `(blog)` (SSR'd for the whole group, `domain-blog`), `(highlights)` (a city's public pages, SSR'd for the group, `domain-venues-and-reports`: its month `/<city>/<month>` and its quarter of food trends `/<city>/trends/<YYYY>-q<N>`), `(server-only)` (sitemaps), `[...catchall]` (SSR'd 404). `constants/BASE_META_TAGS.ts`, `constants/OG_IMAGE.ts`, `lib/api.ts` (`createLoadApi`), `lib/sitemap.ts`, `components/SafeJsonLd.svelte`. Backend `modules/sitemap`.

## Rules

- **SSR is opt-in per route, and an SSR'd route declares its own `pageMetaTags`.** Re-enable with `export const ssr = true` on the `+page.ts`. A `+layout.ts` that turns SSR on turns it on for every child: private children set `ssr = false` again, or they render logged-out on the server and never match the client.
- A layout's `load` under the root's `ssr = false` never runs on the server, so its data is missing from `page.data` in the server render: an SSR'd page that needs data loads it itself. `LayoutStore` starts at `width = 0`, so SSR always renders the mobile branch. Server routes build their client with `createLoadApi(fetch)`; the `api` singleton's global `fetch` throws on a relative `PUBLIC_API_URL`.
- **Meta tags**: `BASE_META_TAGS` is merged under every route's `pageMetaTags`, so a route states only what is its own, but always `canonical` and the OG `url` / `title`, or it declares itself a duplicate of the homepage. Title template is `%s | Munchwerk`; titles and descriptions follow the `brand` skill's patterns; only the homepage leads with the brand; OG/Twitter titles drop the suffix (`og:site_name` carries it). Every page has its own title from its `+page.ts` (or section `+layout.ts`); private pages add `robots: 'noindex, nofollow'`. Verify with `curl`, not devtools. A private page reached by link and SSR'd for its preview (`/r/[token]`, a shared report) keeps the `noindex` and stays out of `robots.txt`, so a crawler that gets the URL can read the `noindex`; its load must not have side effects (count views from `onMount`), since previews and the server render run it.
- **Crawlable lists seed `SlideFetcher`'s `initialItems` / `initialTotalItems` / `initialPage` from the load.** Never gate the seed on `browser` (universal loads re-run on the client and a `!browser` guard hands it a null seed). Only seed a URL with no filter/sort params, since a seeded page is never refetched. Page size, `populate` and sort must match the component's.
- **Social cards are `og.png` server routes** (satori), one per shareable entity. Satori renders statically: plain flex, literal colours, no tokens or interactive components. An `<img>` is sized in `style` (`width: …px; height: …px`): the markup reaches satori as a string, so `width="…"` attributes arrive as text and satori drops the image without a word. The drawn wordmark for a card is `ogWordmark(fill, height)` (`lib/og-image.ts`), and stored ImageKit URLs already carry `?updatedAt=…`, so append transforms with `&tr=`, or satori silently drops the image.
- **Cards draw in the brand's faces through `ogFonts()` (`lib/og-fonts.ts`)**, passed as `fonts` to every `ImageResponse`: static `.woff` files under `lib/og-fonts/` (satori reads no woff2 and no variable axes) loaded once with `read()`; a card names them in inline styles (`font-family: 'Bricolage Grotesque'; font-weight: 800`). Colours are the brand tokens as literals.
- **A card that fails answers an empty reply, not a 500, and logs nothing.** `ImageResponse` renders inside the body stream after the route has returned, so a render error kills the connection before headers, and `debug: false` silences the library's logger: set `debug: true` on the route to see the cause in the dev output. `@ethercorps/sveltekit-og` is in `ssr.external` (`vite.config.ts`) so Node loads it once: inlined by Vite (its `svelte` export condition), every full SSR reload re-ran its resvg loader, whose second `initWasm()` on the native, already initialised `@resvg/resvg-wasm` throws, and every card dropped until the dev process restarted. A Vite restart from a config edit runs in the same process, so a stuck dev server needs a process restart.
- **A top-level dynamic route sits behind param matchers** (`src/params.ts`, SvelteKit 3's one `defineParams` file): `/<city>/<month>` is `[city=city]/[month=month]`, the city a slug that is none of the app's top-level paths, the month `YYYY-MM`, so anything else falls through to `[...catchall]`; the food trends quarter is `[city=city]/trends/[quarter=quarter]` (`YYYY-qN`, lowercase q), a static `trends` segment, so it never meets the month matcher. Matchers are synchronous and also run in the browser, so whether the city exists is the load's question: an unknown city or unpublished month is `error(404)` from the API's 404, a failing API a 503. Static segments win over a matched one anyway (`/blog/2026-10` is the blog's).
- **A card goes to `ImageResponse` as `satoriMarkup(Component, props)` (`lib/og-image.ts`), never as the component.** Satori prints entities as they come and Svelte escapes `&` and `<` in text, so a card handed over as a component shows "&amp;". The helper renders it with `svelte/server`, decodes `&amp;` and turns `&lt;` into the look-alike `‹`, so user text never opens a tag. The blog's `og.png`, the city month's and the food trends quarter's `[card=card].png` (`og` 1200×630, `square` 1080×1080, `portrait` 1080×1350 from one component each, sizes from `HIGHLIGHT_CARDS`) use it. `{@html}` is no way round it: satori drops the text between Svelte's markers.
- JSON-LD holding user text renders through `SafeJsonLd` (`svelte-meta-tags`' `JsonLd` does not escape `<`).
- **The sitemap is sections.** A backend module with public pages registers a `SitemapSection` (`name` of lowercase letters, `count`, `list`) with `SitemapService.register` in its `onModuleInit` (`BlogService` registers `blog` and `blogtags`, `CityHighlightService` `highlights`: published months only, `FoodTrendsReportService` `foodtrends`: published quarters only); `/sitemap.xml` lists `sitemap-static.xml` plus `sitemap-<name>-<page>.xml` per page of every section. Static public pages go in `sitemap-static.xml`.
- **`static/robots.txt` and the sitemaps must agree**: a disallowed URL is never submitted. Unknown URLs answer 404 on the server through `[...catchall]`.
- In-page jumps go through `lib/hash-jump.ts`, not a bare `href="#id"`.
